01

Wazuh Agent Deployment

Установка, настройка и подключение Windows Agent к Wazuh Manager.

Описание работы

Цель

Развернуть Windows Agent и подключить его к Wazuh Manager для централизованного сбора системных событий и событий безопасности Windows. Проверить доступность менеджера, работоспособность агента и успешность установки соединения.

Среда

ОС: Windows 11.
SIEM: Wazuh 4.14.8.
Лабораторная инфраструктура: VirtualBox.
Windows IP: 192.168.1.9.
Wazuh Manager IP: 192.168.1.3.
Порт подключения: TCP 1514.
Сетевой интерфейс: Ethernet.

Инструменты

Wazuh Manager — централизованный сбор и анализ событий.
Wazuh Windows Agent — передача событий с Windows.
Windows PowerShell — управление службой и диагностика подключения.
Test-NetConnection — проверка доступности TCP-порта.
Select-String — проверка состояния агента в файле.
ossec.conf — конфигурация Windows Agent.

Процесс

1. Установлен Wazuh Windows Agent на локальный компьютер.
2. В ossec.conf указан IP-адрес Wazuh Manager.
3. Перезапущена служба агента командой Restart-Service WazuhSvc.
4. Проверено сетевое соединение командой Test-NetConnection 192.168.1.3 -Port 1514.
5. Проверен статус агента в wazuh-agent.state с помощью Select-String.

Анализ

В результате сетевой проверки получено значение TcpTestSucceeded: True, подтверждающее успешное TCP-соединение с Wazuh Manager на порту 1514. Адрес источника соединения — 192.168.1.9, адрес назначения — 192.168.1.3. В файле состояния агента обнаружено значение status='connected'. Дополнительно в Wazuh Dashboard отображается агент amal с ID 001 и статусом Active. Полученные результаты подтверждают успешное подключение Windows Agent к Wazuh Manager.

Вывод

Windows Agent успешно подключён к Wazuh Manager. Проверены сетевой доступ к серверу, доступность TCP-порта 1514 и состояние подключения агента. Получен практический опыт установки и настройки Wazuh Agent, работы с конфигурационным файлом ossec.conf и диагностики соединения с помощью Windows PowerShell. Подготовлена лабораторная среда для дальнейшего мониторинга событий безопасности Windows.

Практическая работа выполнена в собственной лабораторной среде.
02

SIEM Wazuh — Windows Event Analysis (4688)

Просмотр и анализ событий создания процессов Windows через Wazuh SIEM.

Описание работы

Цель

Изучить механизм регистрации создания процессов в Windows и научиться анализировать соответствующие события безопасности через Wazuh SIEM. Определить, какой процесс был запущен, каким процессом он был вызван и от имени какой учётной записи выполнялось действие.

Среда

ОС: Windows 10 Home 22H2.
SIEM: Wazuh 4.14.8.
Источник событий: Windows Security.
Event ID: 4688.
Windows Agent: amal (ID 001).
Лабораторная инфраструктура: VirtualBox.

Инструменты

Wazuh Dashboard — просмотр и анализ событий безопасности.
Wazuh Windows Agent — передача событий на менеджер.
Windows Event Viewer — проверка системных журналов.
Windows Security Audit — регистрация создания процессов.
MITRE ATT&CK — справочник для классификации потенциально подозрительной активности.

Процесс

1. Открыт раздел Threat Hunting в Wazuh Dashboard.
2. Найдено событие Windows Security с Event ID 4688.
3. Изучены сведения о новом процессе и родительском процессе.
4. Проверены идентификаторы процессов (PID), учётная запись и домен.
5. Проанализирована связь между родительским и созданным процессами.

Анализ

В исследуемом событии зарегистрировано создание процесса SearchProtocolHost.exe, расположенного в C:\Windows\System32. В качестве родительского процесса указан SearchIndexer.exe. Оба процесса относятся к компонентам Windows Search. В событии также указаны имя пользователя amal, домен DENIS, идентификаторы процессов и SID учётной записи. Наблюдаемая связь процессов соответствует работе службы поиска Windows. Само по себе событие 4688 не свидетельствует о вредоносной активности.

Вывод

Изучено событие Windows Security Event ID 4688 и подтверждена его передача в Wazuh SIEM. Получен практический опыт анализа создания процессов, определения родительского процесса, изучения PID и сопоставления активности с учётной записью пользователя. Понимание этих полей помогает SOC-аналитику оценивать контекст запуска процессов и выявлять потенциально подозрительную активность.

Практическая работа выполнена в собственной лабораторной среде.
3

Vulnerability Remediation — WinRAR CVE-2023-38831

Обнаружение уязвимой версии WinRAR через Wazuh, изучение CVE и обновление программного обеспечения для устранения известной уязвимости.

Описание работы

Цель

Выявить уязвимое программное обеспечение на рабочей станции, изучить сведения о CVE-2023-38831 и устранить уязвимость путём обновления WinRAR до актуальной версии.

Среда

ОС: Windows 10 Home 22H2.
SIEM: Wazuh 4.14.8.
Агент: amal (ID 001).
Уязвимое ПО: RARLAB WinRAR.
Обнаруженная версия в Wazuh Inventory: 6.21.0.
Проверенная версия файла WinRAR.exe: 7.23.0.
CVE: CVE-2023-38831.

Инструменты

Wazuh Vulnerability Detection — обнаружение уязвимого ПО.
Wazuh Inventory — просмотр сведений об установленных пакетах.
Wazuh CTI — изучение информации об уязвимости.
PowerShell — проверка версии исполняемого файла.
CVE Database — изучение описания и характеристик CVE.

Процесс

1. В Wazuh Vulnerability Detection обнаружена запись о WinRAR версии 6.21.0 с уязвимостью CVE-2023-38831.
2. Изучено описание CVE и диапазон затронутых версий.
3. Определено, что уязвимость затрагивает версии WinRAR до 6.23.
4. Выполнено обновление WinRAR до версии 7.23.0.
5. Через PowerShell проверена версия файла WinRAR.exe с использованием свойства VersionInfo.
6. Полученный результат сопоставлен с информацией из Wazuh Inventory.

Анализ

CVE-2023-38831 — уязвимость WinRAR, позволяющая выполнить произвольный код при попытке пользователя просмотреть обычный файл внутри специально сформированного ZIP-архива. Уязвимость затрагивает версии до 6.23.

В Wazuh Inventory обнаружена версия 6.21.0, отмеченная как уязвимая. После обновления PowerShell показал следующие значения:
ProductName: WinRAR.
ProductVersion: 7.23.0.
FileVersion: 7.23.0.

Таким образом, локальная проверка исполняемого файла подтвердила наличие версии 7.23.0. При этом в отображённой записи Wazuh Inventory ещё оставалась версия 6.21.0. Для окончательного подтверждения устранения уязвимости требуется обновлённая инвентаризация агента и проверка статуса CVE в Wazuh.

Вывод

Обнаружена и исследована уязвимость CVE-2023-38831 в WinRAR. Выполнено обновление программного обеспечения до версии 7.23.0 и проверена версия исполняемого файла через PowerShell. Практика позволила изучить процесс Vulnerability Management: обнаружение уязвимости, анализ CVE, обновление ПО и проверка результата средствами SIEM.

Практическая работа: обнаружение CVE, обновление уязвимого ПО и проверка результата.

Custom Wazuh Detection Rule — Event ID 4625

Создание пользовательского правила для обнаружения неудачных попыток входа в Windows.

Описание работы

Цель

Создать собственное правило обнаружения в Wazuh SIEM для обработки события Windows Security Event ID 4625. Настроить отдельный уровень важности алерта и проверить работу пользовательского правила на реальном событии из лабораторной Windows-системы.

Среда

ОС: Windows 10 Home 22H2.
SIEM: Wazuh 4.14.8.
Сервер: Wazuh Manager.
Агент: amal (ID 001).
Источник события: Windows Security.
Конфигурационный файл: /var/ossec/etc/rules/local_rules.xml.
Событие: Event ID 4625.

Инструменты

Wazuh Manager — обработка событий и применение правил.
Wazuh Dashboard — просмотр и проверка алертов.
local_rules.xml — создание пользовательского правила.
Nano — редактирование конфигурационного файла.
wazuh-analysisd — проверка корректности конфигурации.
systemctl — перезапуск службы Wazuh Manager.

Процесс

1. Найдено стандартное правило Wazuh с ID 60105, обрабатывающее события неудачного входа Windows, включая Event ID 4625.
2. Открыт файл /var/ossec/etc/rules/local_rules.xml.
3. Внутри группы local создано пользовательское правило с ID 100100.
4. Добавлено условие <if_sid>60105</if_sid>, связывающее пользовательское правило со стандартным.
5. Установлен уровень важности level="10".
6. Добавлены описание и группы windows, authentication_failed и custom_alert.
7. Выполнена проверка конфигурации командой wazuh-analysisd -t, после чего перезапущен Wazuh Manager.
8. Проверено срабатывание правила на событии 4625.

Анализ

После настройки и тестирования Wazuh успешно обработал событие Windows Security Event ID 4625. В деталях алерта отображается пользовательское правило 100100 с уровнем важности 10. Описание алерта: Windows Security: Failed Logon Attempt (Event ID 4625). В группах указаны windows, authentication_failed и custom_alert. Результат подтверждает, что пользовательское правило было загружено менеджером и успешно применено к соответствующему событию.

Вывод

Создано и протестировано пользовательское правило Wazuh для обнаружения неудачных попыток входа в Windows. Изучена связь между стандартными и пользовательскими правилами через механизм if_sid. Получен практический опыт редактирования local_rules.xml, настройки уровня важности алерта, проверки конфигурации и тестирования обнаружения. Результат подтвердил возможность расширения стандартных механизмов обнаружения Wazuh под задачи мониторинга SOC.

Практическая работа выполнена и проверена в собственной лабораторной среде.

Изучить событие 4625, определить причину неудачной аутентификации и научиться анализировать связанные с ним поля в Windows Security Logs.

Windows 10 Home 22H2, Wazuh 4.14.8, Windows Security Event Log. Анализ события, полученного от Windows Agent.

Computer: Denis.
Subject: DENIS$ (WORKGROUP).

PowerShell SOC Automation — Failed Logon Analyzer

Автоматизация первичного анализа неудачных попыток входа Windows Event ID 4625 с помощью PowerShell.

Описание работы

Цель

Разработать PowerShell-скрипт для автоматизации первичного анализа Windows Security Event ID 4625. Сократить ручную обработку событий и упростить поиск повторяющихся неудачных попыток аутентификации.

Среда

ОС: Windows 10 Home 22H2.
Источник данных: Windows Security Log.
Событие: Event ID 4625.
Период анализа: последние 24 часа.
Скрипт: SOC-4625-Triage.ps1.

Инструменты

PowerShell — автоматизация анализа.
Get-WinEvent — получение событий Windows.
XML — обработка структуры Event Data.
PSCustomObject — формирование структурированных результатов.
Group-Object — группировка попыток.
Export-Csv — сохранение отчёта.
Sort-Object и Format-Table — сортировка и отображение результатов.

Процесс

1. Создан PowerShell-скрипт SOC-4625-Triage.ps1.
2. Настроен поиск событий Event ID 4625 в журнале Security за последние 24 часа.
3. Реализовано извлечение XML Event Data.
4. Извлечены поля Username, SourceIP, Workstation, LogonType, Status и SubStatus.
5. Результаты преобразованы в структурированные объекты.
6. Реализованы сортировка событий и группировка комбинаций IP-адресов и пользователей.
7. Результаты сохранены в CSV-файл SOC-4625-Report.csv.

Анализ

При тестовом запуске скрипт обнаружил одну неудачную попытку входа:
Event ID: 4625.
TimeCreated: 04.11.2026 19:48:06.
Username: не указан в извлечённых данных.
SourceIP: 127.0.0.1.
LogonType: 2.

Скрипт также вывел группировку попыток по IP-адресу и имени пользователя. Для обнаруженной записи получена комбинация 127.0.0.1 | - с количеством 1.

Сформирован CSV-отчёт: SOC-4625-Report.csv. Его можно использовать для дальнейшего изучения событий и документирования результатов анализа.

Вывод

Разработан и протестирован PowerShell-скрипт для автоматизированного сбора и первичной обработки событий Windows Security Event ID 4625. Получен практический опыт работы с Windows Event Logs, XML, структурированными объектами PowerShell, группировкой данных и экспортом CSV. Скрипт демонстрирует возможность автоматизировать повторяющиеся задачи SOC L1 и расширять их функциональность дополнительными модулями и библиотеками.

Практическая работа: PowerShell scripting, Windows Event Log analysis и SOC L1 automation.
